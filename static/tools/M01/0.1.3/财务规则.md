# M01 财务规则

应用0.1.1，规则M01-2026-10-04.2，schema_version 1。依据：本项目确定性管理分析规格及用户确认的管理口径；2026-10-04形成，适用期由开始/结束期间配置。没有自动收入确认、资本化、税率、会计政策或法定利润表判断。财务人员自行保证来源口径一致。

1. 记录ID全表唯一；编号保留文本前导零。每个业务组合只能一行，重复整组异常；客户产品项目必须显式有值（不适用可填明确类别）。收入/成本/费用不能由多事实表直接多对多连接。
2. 期间YYYY-MM、币种三个大写字母、单位元/千元/万元，严格一致纳入，范围外单列保留来源，不自动换算。无效期间币种单位记异常；起止范围必须有效。
3. 金额最多6位小数、24位数字。拒绝超安全数值，建议原始金额以文本存储。Decimal60位精度计算，利润金额保持原精度，不用浮点。空不是零；成本和直接费用都必须提供静态金额及依据，否则对应层级为空。明确没有成本/费用须填0并注明依据。退款/冲回允许负金额。
4. 毛利=收入−直接成本；直接贡献=毛利−直接费用；分摊后贡献=直接贡献−共用费用。成本缺失不称利润；直接费用缺失保留毛利，不计算贡献。任何源资料异常可能使收入与利润成为局部结果，状态明确显示；费用池或业务异常阻塞整个分摊后贡献层级。
5. 费用池同期间/币种/单位分摊；范围全部(*必须显式)、客户、产品、项目精确匹配。基础：正收入=max(收入,0)、权重非负、平均=1。权重空/负时权重法阻塞；其他基础不采用该权重并保留提示。零基础或无对象不强摊。成本缺失的对象仍参与费用分摊，但其利润不完整。负费用池用于人工确认冲回。
6. 分摊小数位0—6（默认2）；池金额超精度拒绝，不能静默舍入。按基数比例分配并ROUND_HALF_UP至精度，尾差池金额−舍入合计归最大基数对象，同基数ID字典序优先。基数0也保留分摊行0。多费用池允许同对象叠加，逐池守恒。完整金额相等才通过；容差为人工残余复核重要性，不用于自动调平或判定完整。份额/未舍入展示12位仅为说明，不参与回算。
7. 汇总按期间+选定维度，各层任何明细不完整则组利润为空，保留该组收入。利润率=汇总利润/汇总收入×100，收入≤0不适用，保留负利润；不平均行利润率，不把贡献解释为因果。
8. 行分类恰好一次（纳入/范围外/异常）；分摊同时追溯费用池及业务来源，异常保留全部原值。池残余=原金额−实摊，不隐藏。人工复核不能修改结果或解除数据阻塞。源数据或口径改变清旧复核；恢复按原始行重算。
9. 文件限制10MB/实际解压30MB/20000数据行/200列/单元格10000字，公式不执行，宏及外链ZIP拒绝。恢复工作同限，严格版本，含数据与否校验；本款无默认持久化/上传/遥测/外部请求。
10. 分摊过程最多100000行，超过时整体计算拒绝并提示缩小范围，不截断或导出部分成功结果。原始资料仍完整留在内存，可调整期间/币种/范围后重算。
11. 本页可保存逐池人工分摊基础/范围与依据，参数优先于池原始规则；原始费用金额、金额依据和来源保持不变。保存/撤销清结果及复核，换费用池清全部人工分摊规则。工作/方案携带规则；失效费用池ID阻塞计算，不静默忽略。
