# R03 回款对账

应用0.1.0，源码候选，尚未正式打包/官网验收。用于中国企业财务人员将本次工作应收余额、银行回款和人工分配核对，形成可追查核销底稿。首版没有自动记账、银行联网、AI/OCR、收入确认或完整应收平台。

## 完整工作链

工作总览 → 应收单据 → 银行回款 → 候选规则 → 候选与确认 → 核销与撤销 → 截止余额与待办 → 来源与底稿。

1. 确定开始日、截止日和金额精度。应收未结额必须剔除本工作开始前已核销部分，回款只包含本工作范围；不要把历史已核销余额再次导入。
2. 下载中文模板，导入UTF-8 CSV或XLSX；选择页签与表头行，预览后确认。三类资料可分别导入。没有自动共享R01资料，用户主动将已整理的明确ID资料按本款模板导入。
3. 客户ID、币种、单位、含税口径须一致。同名客户不合并，前导零保留；元、分、万元不自动换算，币种不自动换汇。空值不当零。金额十进制文本最多6位小数，超过所选精度拒绝。
4. 候选条件为明确关联ID或同客户ID，日期窗口/容差/排序仅影响候选。多候选必须逐项复核；一个候选也不会自动核销。无候选仍可主动新增有依据的人工分配。
5. 每条分配明确核销ID、票ID、款ID、金额、生效日与依据，可先存草稿再逐项确认。一款多票/多款一票逐行维护，重复票款关系应修订原记录，不能新增重复分配。确认后重新计算才知道是否有效；超额/重复/无效关系沿整个关联组阻塞。
6. 退款填负数、关联原收款ID；退款分配关联原正核销ID，金额为负数。红字应收关联原应收ID，金额为负数、需批准依据；累计不可超原票额。普通负收款不能取绝对值匹配。按每日累计容量防止后续退款掩盖历史超额（不覆盖日内时序）。
7. 票款/规则变化时旧确认全部失效，须复核并重新确认。撤销保留原金额和依据，不删除记录。换资料前后值及修订详情在事件内存中保存，可随完整工作下载；来源按钮展示当前关联资料原行，历史替换前原值查变更事件。
8. 核对分组票款守恒、未核销/未分配、异常隔离、未来/范围外记录。不能跨币种加总；不可解析金额单列“不可量化”，不填零。容差不调平/免除超额。
9. 下载12类XLSX完整底稿（参数版本、分组守恒、逐票余额、逐款余额、候选解释、核销全记录、来源索引、异常、三类原始资料、事件）。金额为十进制文本；有问题的底稿标“待复核”。
10. 保存含数据完整工作或不含数据方案（schema_version=1）。含数据文件有客户/金额/事件，请自行安全保存；无数据方案只保存参数，恢复会清空当前资料。恢复取消保留原工作；当前版本严格校验并从原始资料重算。

## 安全与限制

文件10MB，工作JSON10MB，XLSX解压30MB/2000条目，20000行/200列，单元格10000字；候选5000条或10万次组合检查；事件1000条且整工作保存不超10MB，完整底稿100万单元格/10MB，超限提示减少资料。只有浏览器内存处理，无上传、日志、遥测、CDN、字体/外部请求或默认持久化；宏、公式、缓存、外链、任意用户代码不执行。关闭/确认退出清除工作，须主动下载才能恢复。

财务输入由用户确认，核销底稿不是会计分录。合同额、开票、回款和收入各自不同，不能据回款推断收入；规则与中国适用边界见财务规则/参考来源。
