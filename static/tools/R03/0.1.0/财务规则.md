# R03 财务规则

版本R03-2026-10-03.1；应用0.1.0；适用中国企业人工回款核对底稿。数学规则生效2026-10-03，无预设税率/自动记账政策。应收输入为本工作开始前未结额加本工作新应收，用户负责避免重复包含历史已核销；银行回款只含工作起止期间记录。规则精度/容差、日期范围用户明确保存。

1. 客户ID（姓名只展示）、币种、单位（元/分/万元）、含税口径须完全一致，编号保留前导零，不自动trim或忽略大小写，不换汇换单位。金额Decimal，最多6位小数且不得超过用户精度；不静默舍入。容差仅产生候选，不免除超额、不消差。
2. 唯一稳定票/款/核销ID；重复整组阻塞。普通应收/收款金额>=0；核销必须>0。红字应收和退款必须<0、明确关联原票/原款且有依据。退款分配必须负数并关联原正核销，不超过其可逆转金额；红字累计不得超过原票未结额。只提供明确有依据场景，不自动判断其他负数含义。
3. 核销记录分草稿、确认、撤销、失效；只有确认且合法的记录影响余额。换数据或规则参数使旧确认全部失效，保留原依据与变更事件，重新确认前须复核；撤销保留依据和原行。不运行输入公式/缓存/宏/外链/代码。
4. 票款关联、重复、超额、无效ID、口径不一致均沿票款/退款/红字/逆转关系连通整组阻塞，不按输入顺序抢余额。既不取第一条也不部分採用超额组。草稿/撤销/失效仅留痕，不参与容量占用。
5. 票可早于起始日；本期回款和核销必须在开始日—截止日。未来票款/核销分列，不回写截止余额；确认日期不得早于票款发生。截止之前退款逆转不能引用未来核销。
6. 每客户/币种/单位/含税口径分组：本期可解析收款全额=有效有符号核销+未分配+异常隔离；应收净额=有效净核销+未核销+异常隔离。红字计入负应收调整，退款计入负收款和负核销；无效金额单列“不可量化”不补零。未来额独立列，不跨币种加总。异常票款不隐藏；逾期只判断到期日早于截止日且余额>0。
7. 合同额、开票额、实际回款、收入不同。本款依据收入准则2017第四–六条保留此边界，不从匹配推断收入，不确认履约义务或坏账、银行手续费、税务、账务抵销资格；不确定政策阻塞自动能力。中国适用及实施日期详参考来源。

补充日期容量检查：不仅核对截止净額，还按生效日汇总每日累计核销与当日累计红字调整后的票余额。历史超额不能靠后续退款掩盖。同日多条以日终汇总检查（输入无时分秒，不承诺日内先后），需要日内顺序核验的场景应由用户另行复核。
