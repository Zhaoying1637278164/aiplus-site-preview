# E02 财务规则

规则版本 E02-2026-10-04.2；适用于已确认两个月工资明细的核对。此为企业管理核对算法，依据本款用户任务及2026-10-04项目规则，不是法定工资/税务政策。企业依据、企业规则版本、生效月份、阈值由用户确认，默认内容须替换；生效月不得晚于上期。

- 粒度：每期员工稳定ID×统一薪项，一键一行；不按姓名关联，不猜测改号。同名不同ID不合并。重复键及映射碰撞全部阻塞该键两侧。
- 期间：明确YYYY-MM，先后次序正确；每行须对应所属侧期间。币种完全等于指定币种，单位首版仅元；不换汇、不把万元自动当元。
- 金额：Decimal.js 10.6.0，60位运算精度；十进制最多两位小数、最多24位数字。空值/公式/非法金额不为零；零合法，负值原符号。不能以容差修正金额。
- 无记录与空金额不同：单侧无记录只作为结构性出现/消失贡献，金额显示缺少记录；同员工另一薪项缺失为薪项变化。人员仅本期/仅上期出现，不证明真实入职/离职，需另取HR证据。
- 差额＝本期可核对金额−上期可核对金额。新增贡献＋退出贡献＋同人薪项贡献＝总差额；残差单列。每期员工出现集合包括无效行，避免把金额阻塞误判为退出。阻塞对应键不计可核对金额；保留已知排除金额、未知金额行和原始来源。不完整资料不得宣称完整核对通过。
- 重要变动＝abs(差额)≥用户金额阈值；默认500元仅虚构示例。勾稽容差默认0.01元是复核参数；本算法精确差额残差应为0.00。规则参数与版本、字段对应随底稿导出。
- 个税社保法定自动计算未实现；工资项目包括税或社保时，仅核对用户已提供静态金额。

0.2.0补充：两侧业务字段必须一对一映射原列，碰撞阻塞整次核对，不复用员工列作姓名等字段。结构性不存在记录不补零显示；计算贡献的0只用于集合差额分解。方案0.1.0规则版本与0.2.0不同，拒绝恢复旧版，原包仍独立可用。新增结果JSON含完整来源/异常/规则/参数/复核。所有分页无截断，页100条。
