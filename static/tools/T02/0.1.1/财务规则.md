# T02 财务规则 · T02-2026-10-04.1
适用2026-10-04版，企业自有账户静态日末资料。本款是资金日报复核底稿，无税务/法定报表政策。

- 主体、账户ID、币种、单位、日期和日末时点分开；同名账户以稳定ID区分。不换汇，按主体/日期/币种/单位合并。
- 实际收入和实际支出使用decimal.js 10.6.0，40位计算精度，输入24数字位/6小数位；容差独立配置，只用于余额差。期初＋收入−支出＝计算期末，差额＝计算−独立期末。未知不补零；差异不改原值。
- 收付款稳定ID重复整组隔离，包括其中的空金额；0有效，负数须明确收入/支出及冲回依据，按原方向原符号计算。非法日期/账户/单位/币种/空金额隔离且阻塞相应日结。
- 调拨必须不同账户、同主体币种单位日期、正金额完全相等、反向、双方有效且未批准；双边均保留账户变动和源行，只在合并外部收支剔除。无自动确认/补建/跨日配平/部分分摊；不完全匹配留待完成。
- 分类规则提供建议，逐项批准类别及依据；未分类原行仍在实际收支中，不塞入经营现金流类别。日报不是法定现金流量表。
- 首日独立期初必须有依据；空期初仅从前一日历日同账户范围已批准且有效日结计算余额结转。必须有当日日末独立期末，无交易需明确依据。先维护完整期间资料再逐日批准；修改输入导致所有旧批准失效，须重新按日复核。
- 可用资金按已核对有效期末扣已批准日末受限/锁定；没有依据未知；明确零限制必须单条金额0与依据批准。对象ID代表同一资金限制，重复/重叠不重复扣；合计超余额、负限制、时点不符、已支付再次锁定均阻塞。不包含自动付款。
- 文件、账户、余额、规则、范围、容差变更增加revision，历史事件保留但失效；保留旧汇总比较基线。复核说明不会消除财务阻塞。
- 完整工作schema_version=1且应用/规则版本严格校验；无数据方案只含公开容差，不含账户、主体、私有分类、原数据、事件、复核或基线。
- CSV/XLSX静态值本地内存；拒绝公式/缓存/宏/外链；10MB、实际解压30MB、20000行/200列、100规则。任何用户文本只作为显示/静态单元格，不执行。
